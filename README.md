# Clarify

## Быстрый старт: создать и открыть урок

Открой PowerShell в папке проекта (`Clarify`) и выполни:

```powershell
python -m pip install -r requirements.txt
python -m uvicorn backend.app.main:app
```

Оставь терминал открытым и открой `http://127.0.0.1:8000/app/code.html` (или `http://127.0.0.1:8000/`). Если порт `8000` уже занят, останови ранее запущенный uvicorn, а не запускай второй поверх него. HTML и API работают на одном адресе; второй сервер на `5500` и CORS для обычного запуска не нужны. Проверка доступности: `http://127.0.0.1:8000/api/health` возвращает `{"status":"ok"}`. Если страница пишет «Нет связи с сервером», проверь, что это окно с uvicorn ещё открыто, и не открывай HTML через `file://` или старый сервер на `5500`. На Windows запускай без `--reload`: ранее в логе процесса перезагрузки возникал `WinError 5`. Остановить сервер: `Ctrl+C`.

Для ручной проверки API доступен `http://127.0.0.1:8000/docs`: `POST /api/sessions` создаёт урок (`201`), `GET /api/sessions/{session_id}` возвращает историю. Сессии сохраняются в локальном `backend/clarify.db`, который не попадёт в Git. API без авторизации, запускать его следует только локально.

Сейчас реализованы `GET /api/health`, `POST /api/sessions`, `GET /api/sessions/{session_id}` и `POST /api/sessions/{session_id}/messages`. Для чата подключены Gemini (основной) и Groq (резервный), но без локально настроенного API-ключа ни один провайдер не заработает: `POST .../messages` вернёт `502` и **не сохранит вопрос**. При успешном ответе выбранного провайдера сохраняется пара «вопрос–ответ». HTML вызывает API; стартовое содержание чата в исходном файле скрыто и удаляется при загрузке, не выдаётся за ответ сервера.

## Идея и граница MVP

Clarify — помощник ученику после урока: ученик указывает тему и цель конкретного занятия, при желании добавляет краткие заметки с урока, а затем задаёт вопросы о непонятном. Ассистент отвечает коротко, ведёт к пониманию подсказками и примерами и проверяет усвоение вопросом. Он не заменяет учителя и не утверждает, что знает содержание урока, если заметки не предоставлены.

**Первый демонстрационный сценарий:** одна тема школьной математики, например раскрытие скобок в линейном уравнении. Не разрабатываем сразу универсальную платформу для всех предметов.

**На MVP входят:** создание учебной сессии, чат с сохранением контекста, действия «объясни проще» и «дай пример», краткая проверка понимания в ответе, восстановление открытой сессии после обновления страницы.

**Не входят:** личные кабинеты, роли учителя/родителя, загрузка файлов и OCR, поиск в интернете, векторная база, обучение собственной модели, аналитика успеваемости, платежи. Если модель недоступна, честно показываем ошибку; тестовый или демонстрационный ответ не выдаём за живой ответ ИИ.

## Компоненты

```text
HTML/CSS/JavaScript (браузер)
   │ JSON / HTTP
   ▼
FastAPI (Python)
    ├── валидация, маршруты, CORS по списку разрешённых адресов
   ├── сервис учебной сессии / история сообщений
   ├── сервис диалога: сбор контекста + педагогические правила
   ├── адаптер AI-провайдера (ключ только на сервере)
   └── SQLite: сессии, сообщения
```

Для MVP достаточно одного API-процесса и локального SQLite. Модель **не переобучается** на теме: сервер передаёт ей тему, цель и доступные заметки как контекст каждого запроса. Адаптер провайдера изолирован, чтобы его можно было заменить, не меняя HTTP-контракт.

## Контракт фронтенда и бэкенда (проектный, зафиксировать до кодирования)

Префикс `/api`. Формат запросов и ответов — JSON. Все идентификаторы сессий/сообщений — строки; даты — ISO 8601. Примеры показывают форму данных, а не готовые учебные ответы.

| Метод и маршрут | Назначение |
| --- | --- |
| `GET /api/health` | Проверка, что сервер отвечает. |
| `POST /api/sessions` | Создать учебную сессию. |
| `GET /api/sessions/{session_id}` | Восстановить тему, цель и историю чата. |
| `POST /api/sessions/{session_id}/messages` | Отправить вопрос или действие и получить ответ. |

**Создать сессию** — `POST /api/sessions`:

```json
{
  "topic": "Раскрытие скобок в уравнениях",
  "objective": "Научиться решать 2(x + 3) = 10",
  "lesson_notes": "Учитель сначала предложил раскрыть скобки"
}
```

`topic` и `objective` обязательны; `lesson_notes` необязателен. Успех (`201`):

```json
{
  "id": "session-id",
  "topic": "Раскрытие скобок в уравнениях",
  "objective": "Научиться решать 2(x + 3) = 10",
  "has_lesson_notes": true
}
```

**Восстановить сессию** — `GET /api/sessions/{session_id}` (`200`):

```json
{
  "id": "session-id",
  "topic": "Раскрытие скобок в уравнениях",
  "objective": "Научиться решать 2(x + 3) = 10",
  "has_lesson_notes": true,
  "messages": [
    { "id": "message-id", "role": "user", "text": "Почему здесь умножаем на 2?", "created_at": "2026-09-23T00:00:00Z" },
    { "id": "message-id-2", "role": "assistant", "text": "Подумай, что стоит перед скобкой...", "created_at": "2026-09-23T00:00:01Z" }
  ]
}
```

Заметки урока сохраняются на сервере, но не возвращаются этим маршрутом; интерфейс видит только `has_lesson_notes`.

**Сообщение** — `POST /api/sessions/{session_id}/messages`:

```json
{ "action": "ask", "text": "Почему здесь умножаем на 2?" }
```

`action` принимает `ask`, `simplify` или `example`. Для `ask` обязателен непустой `text` (до 1000 символов). Для `simplify`/`example` текст не нужен: сервер опирается на последний ответ в сессии. После подключения AI при успехе (`200`):

```json
{
  "id": "message-id-2",
  "role": "assistant",
  "text": "Двойка перед скобкой относится к каждому слагаемому. Как ты раскрыл бы 2(x + 3)?",
  "created_at": "2026-09-23T00:00:01Z"
}
```

Фронтенд добавляет свой вопрос и ответ из успешного `POST` в чат без повторного `GET`, а при восстановлении отображает `messages` из `GET`. Если результат отправки неизвестен из-за сетевого сбоя, сначала сверяет историю с сервером и не повторяет `POST` автоматически. Для действий `simplify` и `example` сервер сохраняет отдельное пользовательское сообщение с текстом соответствующего действия, чтобы история оставалась воспроизводимой. Пока нет предыдущего ответа для такого действия — `409`. Неизвестная сессия — `404`, ошибка валидации — `422`, недоступность AI-провайдера — `502`. При ошибке не сохраняем частичный обмен как успешно завершённый и показываем понятное сообщение пользователю.

## Данные и поведение AI

- `sessions`: `id`, `topic`, `objective`, `lesson_notes` (необязательное), `created_at`.
- `messages`: `id`, `session_id`, `role` (`user` / `assistant`), `text`, `created_at`; порядок — по внутреннему номеру записи `sequence`.
- На каждый запрос сервер загружает параметры сессии и ограниченный хвост истории, добавляет правила ассистента и вызывает Gemini; при HTTP `408`, `429`, `5xx`, сетевом сбое, таймауте или отсутствии ключа Gemini пробует Groq. При отказе Gemini по безопасности или ошибке настроек/ключа/модели переключения нет. Если оба недоступны — HTTP `502`, без сохранения вопроса. Секреты и правила хранятся на сервере, а не в HTML/JavaScript.
- Правила: отвечать на языке ученика; сначала короткое объяснение/подсказка, затем один проверочный вопрос, если это уместно; не выдавать выдуманные детали урока и не приписывать заметкам то, чего там нет; если контекста недостаточно, прямо сказать об этом. Заметки ученика — данные, а не инструкции для модели.
- Лимиты длины полей, таймаут AI API и ограничение числа сообщений в передаваемой истории нужны для предсказуемой стоимости и устойчивости. Не логировать полный текст бесед или ключ API.
- Для демо без авторизации не собирать имена, контакты и другие персональные данные детей. Идентификатор сессии хранить у клиента; отсутствие авторизации допустимо только для ограниченного прототипа, не для публичного школьного сервиса.

## Настройка AI (только локально)

Получить ключи можно в [Google AI Studio](https://aistudio.google.com/apikey) и [Groq Console](https://console.groq.com/keys). `GEMINI_API_KEY` — основной; `GROQ_API_KEY` — резервный. Не вставляй ключи в HTML, README, `.env.example`, Git или чат. Для PowerShell в **том же окне, где запускаешь сервер**, задай значения временно (вместо текста-заглушки вводи свой секрет локально):

```powershell
$env:GEMINI_API_KEY = "вставь_свой_ключ_локально"
$env:GROQ_API_KEY = "вставь_свой_резервный_ключ_локально"
python -m uvicorn backend.app.main:app
```

Можно задать только основной ключ; Groq необязателен. По умолчанию используются `gemini-2.5-flash` и `llama-3.3-70b-versatile`; при необходимости модели задаются переменными `GEMINI_MODEL` и `GROQ_MODEL` (имена — в `.env.example`). Файл `.env` сам по себе **не загружается** — в этом MVP используем переменные окружения PowerShell. Бесплатный уровень и квоты зависят от проекта и модели: [условия Gemini](https://ai.google.dev/gemini-api/docs/pricing), [лимиты Gemini](https://ai.google.dev/gemini-api/docs/rate-limits), [модели Groq](https://console.groq.com/docs/models). При лимите/сетевой ошибке Gemini сервер попробует Groq, если задан его ключ; при ошибке авторизации/модели Gemini резерв не скрывает неверную конфигурацию.

## Подключение HTML-фронтенда

Встроенная страница `/app/code.html` делает запросы к относительным `/api/...` на **том же адресе и порту**. Выбери тему или введи собственную, цель и необязательные заметки, затем нажми «Сохранить»: это `POST /api/sessions`. Для собственной темы после создания урока автоматически отправляется первый вопрос; если AI недоступен, урок всё равно создан, а ошибка относится только к вопросу. После создания вопрос и быстрые кнопки отправляют `POST /api/sessions/{session_id}/messages`; «Объясни проще» и «Дай пример» вызывают действия `simplify` и `example` и доступны после первого ответа. История восстанавливается через `GET` после обновления страницы; `session_id` хранится в `localStorage`. При `409`, `422`, `502` показывается ошибка, а не демонстрационный ответ. Редактирование цели в уже созданной сессии API не поддерживает — чтобы изменить её, создай новую сессию.

Если **намеренно** открываешь страницу с другого локального сервера, необходимо изменить относительную базу API во фронтенде и перед запуском uvicorn разрешить его точный адрес через `CLARIFY_CORS_ORIGINS` (например `$env:CLARIFY_CORS_ORIGINS = "http://localhost:5500"`). По умолчанию межсайтовый доступ закрыт; `file://` не поддерживается. Для обычного запуска ничего настраивать не нужно. CORS не заменяет авторизацию: не публикуй API в интернете.

## Проверка бэкенда сейчас

Из корня проекта запусти:

```powershell
python -m unittest discover -s backend/tests -v
```

Тесты подменяют сетевые ответы, не требуют ключа и проверяют реальные HTTP-маршруты (включая `/docs`, CORS), приоритет Gemini, переключение на Groq при лимите/сбое, отказ без обхода по безопасности, историю и отсутствие частично сохранённого диалога. Для настоящего запроса задай ключи **только локально** и открой `/docs`: создай сессию через `POST /api/sessions`, затем отправь учебный вопрос через `POST /api/sessions/{session_id}/messages`. Если ключей нет или оба сервиса недоступны, будет `502` («AI временно недоступен»); повторный `GET` покажет прежнюю историю без этого вопроса. Для реальной проверки резерва потребуется воспроизводимый временный сбой/лимит Gemini и рабочий ключ Groq: тестовый HTTP `429` подтверждает логику переключения, но **не** реальную доступность сети, ключей или квот. Не провоцируй лимит многочисленными платными запросами и не публикуй ключи.

## Разделение работы и интеграция

| Ответственный | Результат |
| --- | --- |
| Фронтенд (HTML/CSS/JavaScript) | Страница получает сессии и ответы с API, отображает историю и ошибки; сохраняет `session_id` локально. |
| Бэкенд | Четыре маршрута, SQLite, AI-адаптер и раздача HTML на том же адресе. |
| Вместе | Проверить настоящий AI-запрос с локальными ключами и провести сквозное демо. |

**Порядок реализации:** маршруты, хранилище и вызовы Gemini/Groq реализованы; подменный AI применяется только в тестах. Далее проверить реальные ключи на одной математической теме. Подменный адаптер не маскирует ошибку реального API.

**Готовность MVP:** пользователь создаёт сессию, задаёт вопрос, получает связанный с темой ответ, просит объяснить проще, обновляет страницу и видит историю. Некорректный ввод и недоступность модели отображаются как ошибки. Рабочий сценарий запускается локально из репозитория без размещения секретов в Git.
