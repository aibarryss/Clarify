# Clarify

## Быстрый старт: создать урок

Открой PowerShell в папке проекта (`Clarify`) и выполни:

```powershell
python -m pip install -r requirements.txt
python -m uvicorn backend.app.main:app --reload
```

Пока терминал с сервером открыт, зайди на `http://127.0.0.1:8000/api/health`. Ответ `{"status":"ok"}` означает, что сервер работает. Затем открой `http://127.0.0.1:8000/docs`, раскрой `POST /api/sessions`, нажми **Try it out** и **Execute**. В примере запроса укажи тему, цель и, если хочешь, заметки с урока. В ответе увидишь `id` созданной сессии и статус **201**. Остановить сервер: `Ctrl+C` в терминале.

Сессии сохраняются в локальном файле `backend/clarify.db` (он не попадёт в Git). Пока API без авторизации и не предназначен для публикации в интернет; настройку CORS для React добавим при интеграции.

Сейчас реализованы `GET /api/health` и `POST /api/sessions`. Восстановление сессии и чат ниже — согласованный план следующих шагов, пока не работающие функции.

## Идея и граница MVP

Clarify — помощник ученику после урока: ученик указывает тему и цель конкретного занятия, при желании добавляет краткие заметки с урока, а затем задаёт вопросы о непонятном. Ассистент отвечает коротко, ведёт к пониманию подсказками и примерами и проверяет усвоение вопросом. Он не заменяет учителя и не утверждает, что знает содержание урока, если заметки не предоставлены.

**Первый демонстрационный сценарий:** одна тема школьной математики, например раскрытие скобок в линейном уравнении. Не разрабатываем сразу универсальную платформу для всех предметов.

**На MVP входят:** создание учебной сессии, чат с сохранением контекста, действия «объясни проще» и «дай пример», краткая проверка понимания в ответе, восстановление открытой сессии после обновления страницы.

**Не входят:** личные кабинеты, роли учителя/родителя, загрузка файлов и OCR, поиск в интернете, векторная база, обучение собственной модели, аналитика успеваемости, платежи. Если модель недоступна, честно показываем ошибку; тестовый или демонстрационный ответ не выдаём за живой ответ ИИ.

## Компоненты

```text
React (браузер)
   │ JSON / HTTP
   ▼
FastAPI (Python)
   ├── валидация, маршруты, CORS
   ├── сервис учебной сессии / история сообщений
   ├── сервис диалога: сбор контекста + педагогические правила
   ├── адаптер AI-провайдера (ключ только на сервере)
   └── SQLite: сессии, сообщения
```

Для MVP достаточно одного API-процесса и локального SQLite. Модель **не переобучается** на теме: сервер передаёт ей тему, цель и доступные заметки как контекст каждого запроса. Адаптер провайдера изолирован, чтобы его можно было заменить, не меняя HTTP-контракт.

## Контракт фронтенда и бэкенда (проектный, зафиксировать до кодирования)

Префикс `/api`. Формат запросов и ответов — JSON. Все идентификаторы сессий/сообщений — строки; даты — ISO 8601. Примеры показывают форму данных, а не готовые учебные ответы.

| Метод и маршрут | Назначение |
| --- | --- |
| `GET /api/health` | Проверка, что сервер отвечает. |
| `POST /api/sessions` | Создать учебную сессию. |
| `GET /api/sessions/{session_id}` | Восстановить тему, цель и историю чата. |
| `POST /api/sessions/{session_id}/messages` | Отправить вопрос или действие и получить ответ. |

**Создать сессию** — `POST /api/sessions`:

```json
{
  "topic": "Раскрытие скобок в уравнениях",
  "objective": "Научиться решать 2(x + 3) = 10",
  "lesson_notes": "Учитель сначала предложил раскрыть скобки"
}
```

`topic` и `objective` обязательны; `lesson_notes` необязателен. Успех (`201`):

```json
{
  "id": "session-id",
  "topic": "Раскрытие скобок в уравнениях",
  "objective": "Научиться решать 2(x + 3) = 10",
  "has_lesson_notes": true
}
```

**Восстановить сессию** — `GET /api/sessions/{session_id}` (`200`):

```json
{
  "id": "session-id",
  "topic": "Раскрытие скобок в уравнениях",
  "objective": "Научиться решать 2(x + 3) = 10",
  "has_lesson_notes": true,
  "messages": [
    { "id": "message-id", "role": "user", "text": "Почему здесь умножаем на 2?", "created_at": "2026-09-23T00:00:00Z" },
    { "id": "message-id-2", "role": "assistant", "text": "Подумай, что стоит перед скобкой...", "created_at": "2026-09-23T00:00:01Z" }
  ]
}
```

Заметки урока сохраняются на сервере, но не возвращаются этим маршрутом; интерфейс видит только `has_lesson_notes`.

**Сообщение** — `POST /api/sessions/{session_id}/messages`:

```json
{ "action": "ask", "text": "Почему здесь умножаем на 2?" }
```

`action` принимает `ask`, `simplify` или `example`. Для `ask` обязателен непустой `text`. Для `simplify`/`example` текст не нужен: сервер опирается на последний ответ в сессии. При успехе (`200`):

```json
{
  "id": "message-id-2",
  "role": "assistant",
  "text": "Двойка перед скобкой относится к каждому слагаемому. Как ты раскрыл бы 2(x + 3)?",
  "created_at": "2026-09-23T00:00:01Z"
}
```

Фронтенд добавляет свой вопрос в чат после успешного ответа, а при восстановлении отображает `messages` из `GET`. Для действий `simplify` и `example` сервер сохраняет отдельное пользовательское сообщение с текстом соответствующего действия, чтобы история оставалась воспроизводимой. Пока нет предыдущего ответа для такого действия — `409`. Неизвестная сессия — `404`, ошибка валидации — `422`, недоступность AI-провайдера — `502`. При ошибке не сохраняем частичный обмен как успешно завершённый и показываем понятное сообщение пользователю.

## Данные и поведение AI

- `sessions`: `id`, `topic`, `objective`, `lesson_notes` (необязательное), `created_at`.
- `messages`: `id`, `session_id`, `role` (`user` / `assistant`), `text`, `created_at`; порядок — по времени создания и идентификатору.
- На каждый запрос сервер загружает параметры сессии и ограниченный хвост истории, добавляет правила ассистента и вызывает выбранный AI API. Секреты и правила хранятся на сервере, а не в React.
- Правила: отвечать на языке ученика; сначала короткое объяснение/подсказка, затем один проверочный вопрос, если это уместно; не выдавать выдуманные детали урока и не приписывать заметкам то, чего там нет; если контекста недостаточно, прямо сказать об этом. Заметки ученика — данные, а не инструкции для модели.
- Лимиты длины полей, таймаут AI API и ограничение числа сообщений в передаваемой истории нужны для предсказуемой стоимости и устойчивости. Не логировать полный текст бесед или ключ API.
- Для демо без авторизации не собирать имена, контакты и другие персональные данные детей. Идентификатор сессии хранить у клиента; отсутствие авторизации допустимо только для ограниченного прототипа, не для публичного школьного сервиса.

## Разделение работы и интеграция

| Ответственный | Результат |
| --- | --- |
| Фронтенд | Форма темы/цели/заметок, чат, три действия (`ask`/`simplify`/`example`), состояние загрузки и ошибок, сохранение `session_id` для восстановления. |
| Бэкенд | Четыре маршрута выше, SQLite, адаптер AI, валидация/ошибки, разрешённый origin фронтенда в CORS, тесты основного сценария. |
| Вместе | Сверить JSON из этого README, соединить UI с API, провести одно сквозное демо и записать сценарий для защиты. |

**Порядок реализации:** сначала маршруты и хранилище с подменным AI-адаптером для тестов; затем настоящий адаптер и проверка одной математической темы; затем интеграция с React. Подменный адаптер применяется только в тестах или явно отмеченном деморежиме, не маскирует ошибку реального API.

**Готовность MVP:** пользователь создаёт сессию, задаёт вопрос, получает связанный с темой ответ, просит объяснить проще, обновляет страницу и видит историю. Некорректный ввод и недоступность модели отображаются как ошибки. Рабочий сценарий запускается локально из репозитория без размещения секретов в Git.
